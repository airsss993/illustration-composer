# Архитектура

Веб-сервис без сборки и без зависимостей: `server.mjs` (node) отдаёт статику, вся работа идёт
в браузере. Логика вынесена в `web/compose.js` без DOM, тот же модуль гоняют тесты
и скрипт примеров в node.

```
library/*.svg ──> build-manifest.mjs ──> manifest.json
                                              │
palettes.json, examples/layouts.json ─────────┤
                                              v
                 web/app.js (интерфейс) ──> web/compose.js ──> SVG на холсте и в файл
```

## Хранение

- `library/{L,S}/{main,background}/<id>.svg` - объект как его выгрузила Figma, один файл на
  объект, набор и состояние. Внутри только `g` и `path`, цвет только в `fill`/`stroke`.
- `library/backgrounds/<вид>-<Ш>x<В>.svg` - фон под каждый формат холста, 2 вида x 3 формата.
- `library/palettes.json` - схемы. Схема - это 3 фоновых и 3 объектных цвета; позиция цвета
  в списке и есть его роль (`bg1..3`, `obj1..3`), плюс общие `ink` и `white`.
- `library/manifest.json` - опись: габариты, русские названия, роли цветов каждого файла,
  отношение S к L. Собирается `node scripts/build-manifest.mjs`, руками не правится.
  Скрипт падает, если файл нарушает правила: цвет вне схемы, растр, лишние теги,
  объектный цвет у фона или фонового объекта.
- `examples/layouts.json` - раскладки 18 примеров из Figma: какие объекты, в каком
  состоянии, где стоят, какая перестановка ролей цвета.

Добавить объект - положить 4 SVG (L/S x главный/фоновый) и строку в `NAMES` скрипта манифеста.
Добавить схему - строка в `palettes.json` или загрузка JSON в интерфейсе, код не меняется.

## Извлечение

Браузер берёт `manifest.json` и по нему загружает только нужные файлы, с кэшем.
При загрузке файл превращается в шаблон (`toTemplate`): из него вынимается содержимое
корневого `<svg>`, каждый hex меняется на метку роли (`fill="{obj1}"`). Роль определяется
по исходной схеме lilac, в которой нарисована вся библиотека.

## Переиспользование

- Перекраска - подстановка hex текущей схемы в метки ролей (`paint`). Геометрия не трогается.
  Фону и фоновым объектам объектные роли запрещены проверкой в коде, а не договорённостью.
- Экземпляр объекта на холсте - `{ id, state, x, y, rotation, recolor }`. Ни масштаба, ни
  правки путей у экземпляра нет, поэтому пропорции объектов друг к другу сохраняются.
- Набор S - вся композиция вдвое меньше: холст 500x500 вместо 1000x1000, объекты S в родном
  размере. Переключение пересчитывает позиции с сохранением центра.
- Экспорт (`buildSvg`) - один SVG: группа `background` и по группе на экземпляр
  (`id="coin-1"`, `transform="translate(...) rotate(...)"`), внутри исходные пути библиотеки.
  В Figma или Illustrator каждый объект открывается отдельной группой.

## Сборка композиции

1. Запрос -> список объектов. Сценарий 2: названия по началу слова (`монеты`, `кошелёк`).
   Сценарий 1: фраза уходит на `POST /api/metaphor` в `server.mjs`. Сервер передаёт языковой
   модели (OpenAI-совместимый `/chat/completions`) системный промпт: 10 объектов с их смыслом,
   правила выбора и примеры. В ответ приходит JSON с 1-3 id и одним предложением объяснения.
   Id сверяются с библиотекой, чужие отбрасываются. Если модель перегружена или вышла квота,
   запрос уходит к следующей модели из списка. Ключ живёт только на сервере (`LLM_API_KEY`),
   в браузер не попадает. Лимит: 10 запросов в минуту с IP и 500 в сутки на весь сервис.
   Если сервер не ответил (статический хостинг, нет ключа, лимит, ошибка модели), фразу
   разбирает словарь ассоциаций в `compose.js` (`WORDS`): до трёх объектов с наибольшим
   счётом, без сети, но слово вне словаря не распознаётся.
2. Объекты -> раскладка (`compose`). Если состав совпал с примером этого формата, берётся
   его раскладка как есть. Иначе пример с наибольшим числом совпавших объектов: совпавшие
   остаются на своих местах, остальные встают центр в центр на свободные места, ближайшие
   по площади к прежним объектам. При равном совпадении выигрывает пример с лучшей
   подгонкой. Состояние (главный или фоновый) и вид фона берутся из примера.
3. Дальше правка руками: перенос, поворот, дубль, удаление, слои, состояние, формат, схема.

## Проверки

- `node scripts/build-manifest.mjs` - правила библиотеки.
- `node scripts/test-compose.mjs` - 18 примеров собираются в свою раскладку, в 2 наборах
  и 3 схемах нет цвета вне схемы и объектного цвета в фоне; разбор запросов; приём и отказ
  палитры; раскладка неизвестного состава.
- `node scripts/make-examples.mjs` - `examples/composed/`, три композиции тем же кодом.
